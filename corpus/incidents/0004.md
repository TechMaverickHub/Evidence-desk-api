# INC-0004: Spike of 422 responses from the mobile app (synthetic)

> Synthetic incident written for the EvidenceDesk benchmark. Services, people and events are fictional.

## Summary

After mobile release 7.3, the search endpoint returned 422 Unprocessable Entity for about 12% of requests.

## Impact

Search failed for users of the new app version for 6 hours.

## Timeline (UTC)

- 08:00 Mobile 7.3 rolls out to 50% of users.
- 08:30 422 rate on `GET /search` rises to 12%.
- 13:10 Logs show validation errors with type `int_parsing` on the `limit` parameter.
- 14:00 Mobile hotfix 7.3.1 released.

## Root cause

The new app sent `limit=ten` from an untranslated settings string. FastAPI rejected the request with an `int_parsing` validation error because `limit` is declared as `int`. The errors were not visible in dashboards because 4xx responses were not logged with their details.

## Resolution

Mobile hotfix sends a numeric limit. The API now logs validation error types via a `RequestValidationError` exception handler.

## Follow-ups

- Alert on 422 rate per endpoint and client version.
- Contract tests between the mobile client and the API.
