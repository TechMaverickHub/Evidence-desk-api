# INC-0001: 502 Bad Gateway after deploy of orders-api (synthetic)

> Synthetic incident written for the EvidenceDesk benchmark. Services, people and events are fictional.

## Summary

For about five minutes after a deploy, the load balancer returned 502 Bad Gateway for most requests to orders-api.

## Impact

Roughly 40% of checkout requests failed between 09:12 and 09:17 UTC.

## Timeline (UTC)

- 09:10 Deploy of orders-api 4.2.0 starts (rolling, 4 Uvicorn workers per pod).
- 09:12 Load balancer marks new pods healthy; 502 rate rises to 38%.
- 09:15 On-call sees workers still running startup migrations in the logs.
- 09:17 All workers finish startup; 502 rate returns to zero.

## Root cause

Uvicorn workers were still starting while the health check already reported ready. The `/healthz` endpoint returned 200 as soon as the process accepted TCP connections, before the application's lifespan startup had loaded its database pool and cache.

## Resolution

The health check now calls a readiness endpoint that returns 503 until the lifespan startup has finished and the database pool answers a ping.

## Follow-ups

- Separate liveness and readiness endpoints in every service.
- Move schema migrations out of application startup into a release job.
