# INC-0002: Redirects to http:// behind the TLS proxy (synthetic)

> Synthetic incident written for the EvidenceDesk benchmark. Services, people and events are fictional.

## Summary

After moving catalog-api behind a new TLS-terminating proxy, redirects and generated URLs used `http://` instead of `https://`.

## Impact

Browsers showed mixed-content warnings; OAuth callbacks failed for 2 hours.

## Timeline (UTC)

- 13:00 Traffic switched to the new proxy.
- 13:20 First reports of OAuth callback failures (redirect_uri mismatch).
- 14:45 Engineer notices `request.url.scheme` is `http` inside the app.
- 15:05 Fix deployed.

## Root cause

Uvicorn trusts proxy headers only from the addresses in `--forwarded-allow-ips`, which was left at its default (`127.0.0.1` and `::1`). The old proxy ran on the same host; the new one connects from another subnet, so its `X-Forwarded-Proto: https` header was ignored.

## Resolution

Set `--forwarded-allow-ips` to the new proxy's subnet.

## Follow-ups

- Add an integration test that asserts generated URLs use https behind the proxy.
- Never use `--forwarded-allow-ips='*'` on hosts reachable without the proxy.
