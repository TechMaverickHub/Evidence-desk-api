# INC-0013: Internal fields exposed in user API responses (synthetic)

> Synthetic incident written for the EvidenceDesk benchmark. Services, people and events are fictional.

## Summary

`GET /users/{id}` returned the internal `password_hash` and `is_admin` fields.

## Impact

Security incident: hashed passwords of 30 users were visible to other users for 2 days. Hashes were rotated.

## Timeline (UTC)

- Day 1 Refactor returns the database object directly from the endpoint.
- Day 3 Bug bounty report.
- Day 3 Fix deployed; affected users forced to reset passwords.

## Root cause

The endpoint lost its `response_model` during a refactor, so FastAPI serialised every attribute of the returned object.

## Resolution

Restored `response_model=UserPublic` and added a test that fails if unexpected fields appear in the response.

## Follow-ups

- Require `response_model` on every endpoint via a review checklist.
