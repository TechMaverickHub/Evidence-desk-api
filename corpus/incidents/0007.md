# INC-0007: Rate limiter counted each request once instead of twice (synthetic)

> Synthetic incident written for the EvidenceDesk benchmark. Services, people and events are fictional.

## Summary

A quota dependency declared both on the router and on an endpoint was executed only once per request, so the expensive endpoint consumed half the intended quota.

## Impact

One tenant exceeded its export quota by 2x over a week; no outage.

## Timeline (UTC)

- Day 1 Finance notices export volume above contract.
- Day 3 Engineers find `consume_quota` ran once per request.
- Day 4 Fix deployed.

## Root cause

FastAPI caches a dependency's result within a request: when the same dependency is declared more than once, it is called once and the value is reused. The design assumed two calls.

## Resolution

The endpoint-level declaration uses `Depends(consume_quota, use_cache=False)` and a test asserts the quota decreases by two.

## Follow-ups

- Make quota cost an explicit parameter instead of relying on repeated calls.
