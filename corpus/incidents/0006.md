# INC-0006: Latency spike from a blocking call in async endpoint (synthetic)

> Synthetic incident written for the EvidenceDesk benchmark. Services, people and events are fictional.

## Summary

p95 latency of catalog-api rose from 80 ms to 4 s under normal load.

## Impact

All endpoints of catalog-api slowed down for 50 minutes.

## Timeline (UTC)

- 16:00 Release adds a price lookup to `GET /products/{id}`.
- 16:05 p95 latency jumps for every endpoint, not just the changed one.
- 16:40 Profiling shows the event loop blocked in a synchronous database driver.
- 16:50 Fix deployed.

## Root cause

The new code called a synchronous database client inside an `async def` path operation. The blocking call ran on the event loop, so every other request on that worker waited.

## Resolution

The endpoint was changed to a normal `def` function, which FastAPI runs in a threadpool, until the async driver is adopted.

## Follow-ups

- Lint rule against known blocking clients inside `async def` functions.
